# Domain docs

This repo uses a single-context layout:
- GLOSSARY.md at the repo root
- docs/adr/ for architecture decisions

Before exploring, read the glossary and ADRs relevant to the task.
If they do not exist, proceed silently. Domain-modeling creates them
when terms or decisions are resolved.

Use the glossary's terms when naming domain concepts.
Explicitly flag proposals that contradict an existing ADR.
